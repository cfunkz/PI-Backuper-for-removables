Building from source

Run it from Python, build the app for your OS, and run the tests.

Requirements

  • Windows 10/11, macOS 12 or newer, or Linux (Raspberry Pi OS included)
  • Python 3.10 or newer, with Tkinter. The python.org installers include it; on Debian, Ubuntu and Raspberry Pi OS it's sudo apt install python3-tk.
  • On Windows only, the two runtime packages pywin32 and WMI. Linux and macOS need nothing beyond the standard library.

Run from source

git clone https://github.com/cfunkz/PI-Backuper.git
cd PI-Backuper
pip install -r requirements.txt
python main.py

python -m pi_backuper works too. Raw disk access needs Administrator (Windows) or root (macOS, Linux). Start it without and it offers to restart itself with the right permissions: the UAC prompt on Windows, the password dialog on macOS, and pkexec on Linux. Or just start it that way yourself, for example sudo python3 main.py.

Build the app

pip install -r requirements.txt pyinstaller pillow
python build.py

build.py runs PyInstaller with the right options for the OS it's on and puts the result in dist/release/:

OSFileWhat it is
WindowsPI-Backuper-<version>-windows-x64.exeOne portable exe, no console window, asks for admin rights on launch.
macOSPI-Backuper-<version>-macos-arm64.zipA zipped PI-Backuper.app (-x64 when built on an Intel Mac).
LinuxPI-Backuper-<version>-linux-x64.tar.gzOne executable (-arm64 when built on a Pi or other ARM machine).

A Linux build only runs on systems with a glibc at least as new as the one it was built on, so build on the oldest distro you want to support. The official builds use Ubuntu 22.04.

Releases

Releases are built by GitHub Actions. Bump __version__ in pi_backuper/__init__.py (and version in pyproject.toml), commit, then push a matching tag:

git tag v1.2.0
git push origin v1.2.0

The release workflow checks the tag matches __version__, builds Windows x64, macOS arm64 and x64, and Linux x64 and arm64, and publishes them as a GitHub release with a SHA256SUMS.txt. The same builds also run on every pull request (workflow build), so a broken build shows up before you tag, and you can start one by hand from the Actions tab.

Tests

The tests run on any OS:

pip install pytest
python -m pytest

They run backup, restore and clone against fake in-memory disks, and the Linux and macOS disk listing against fake /sys trees and diskutil output. Among other things they check:

  • backup then restore gives back identical data, compressed and uncompressed
  • a gzip image that doesn't end on a sector boundary leaves the rest of that sector alone
  • old MD5 hash files still work
  • a damaged image is refused and the disk is left blank
  • an image too big for the device is refused before anything's written
  • verify catches a card that silently drops writes
  • clone copies everything and refuses a smaller target
  • a cancelled or failed backup leaves no files behind
  • a write error stops the reader thread too
  • a new backup replaces an old hash file
  • on Linux, only USB and SD disks are listed, and never the one the system runs from
  • a card swapped after Refresh is noticed

GitHub Actions runs the tests on Linux, Windows and macOS for every push and pull request, and checks the app imports with each OS's disk code.

Project layout

main.py                  entry point (what PyInstaller builds)
build.py                 builds and packs the app for the current OS
pi_backuper/__init__.py  name, version, author, licence
pi_backuper/__main__.py  lets you run "python -m pi_backuper"
pi_backuper/imaging.py   backup / restore / clone / verify, no OS-specific code
pi_backuper/disks/       finding disks, raw access, locking/unmounting
  windows.py             WMI, \\.\PhysicalDriveN, volume locks
  macos.py               diskutil, /dev/rdiskN
  linux.py               /sys and /proc, /dev/sdX and /dev/mmcblkN
pi_backuper/gui.py       Tkinter window
pi_backuper/fmt.py       "29.7 GB" and "3m 05s left" formatting
tests/                   tests using fake disks, /sys trees and diskutil output
favicon.ico, icon.png    app icon (Windows wants .ico, Tk elsewhere takes .png)
requirements.txt         pywin32, WMI (Windows only)
.github/workflows/       tests, builds, releases
pyproject.toml           package metadata
