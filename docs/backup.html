Backup

Read a whole card into an image file on your PC.

Steps

  1. Choose the card under Device. Shut the Pi down properly before you pull the card, otherwise the backup is of a filesystem that was in the middle of being written.
  2. Click Save as… and pick a file name. You can also type a path straight into the box.
  3. Decide on the two options (see below) and click Start backup.

You'll see two steps in the progress area: Reading (copying the card) and, if verify is on, Verifying (reading the new file back).

Options

Gzip compress backups

On by default. The image is saved as .img.gz. A Pi card is mostly empty space, and empty space compresses to almost nothing, so a 32 GB card with 4 GB used often ends up around 2 to 3 GB.

PI-Backuper uses the fastest gzip level on purpose. Empty space compresses just as well at that level, and anything higher makes the CPU the bottleneck on a fast USB 3 reader.

Ticking or unticking this box switches the extension in the path box between .img and .img.gz for you.

Turn it off if you want a plain .img to open in another tool or mount directly. Plain images are the full size of the card.

Verify after writing

On by default. After the backup is written, the whole file is read back, decompressed and hashed. If the hash doesn't match what came off the card, the backup is thrown away and you get an error. This catches a failing hard drive or USB stick on the PC side. It adds a bit of time, mostly on big uncompressed images.

What you end up with

pihole-2026-10.img.gz
pihole-2026-10.img.gz.hash.txt

The .hash.txt file holds the SHA-256 of the card's contents and its exact size. Restore uses it to check the image hasn't been damaged since. Always copy the two files together. See Verification and hashes for the format.

Checks before it starts

  • The folder has to exist. It won't create one for you.
  • Overwriting asks first. If the file already exists and you didn't just pick it in the Save dialog (which asks on its own), you get a "Replace it?" prompt.
  • You can't save onto the card you're backing up. It checks which physical disk the save folder lives on.
  • Free space. If you're saving uncompressed and the folder has less space than the card, it refuses. If you're compressing, it warns you and lets you try, since compressed images are usually much smaller.
  • Same card as you picked. The disk is looked up again by hardware ID, serial and size, in case cards were swapped since you last pressed Refresh.

While it runs

  • The card's partitions are locked so nothing writes to them during the backup. If Windows won't allow a lock (Explorer has a window open on it, say), you'll get a note telling you not to touch that drive until it's done. The backup still goes ahead.
  • The image is written to name.partial first and only renamed once it's complete, flushed to disk and verified.
  • Your PC is kept awake until the job finishes.

Cancelling

Press Cancel at any time. The .partial file is deleted and you get "Backup cancelled. Nothing was saved." Any older backup with the same name is left untouched, because the new one never got renamed over it.
