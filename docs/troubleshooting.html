Troubleshooting

Error messages, what they mean, and what to try.

Getting started

"Please run PI-Backuper as Administrator"

Raw disk access needs admin rights. Right-click the exe and choose Run as administrator. If you're running from source, open the terminal as Administrator first.

"No removable devices found"

  • Press Refresh after plugging the card in. Some readers take a few seconds to show up.
  • Check Disk Management (diskmgmt.msc). If the card isn't there either, it's the reader, the cable or the card.
  • Built-in laptop card readers on PCIe sometimes report as fixed disks and are filtered out. Use a USB reader.
  • External drives that Windows reports as neither USB nor removable won't be listed. That's on purpose.

Windows SmartScreen blocks the exe

The exe isn't code-signed. Click More info and Run anyway, or build it from source.

Before a job starts

"Couldn't lock E:. Close any Explorer windows or programs using it and try again."

Something has the card open. Close Explorer windows showing the card, any file open from it, and anything like a photo importer or backup tool that grabs new drives. Antivirus scanning a freshly plugged-in drive is another common cause; wait a minute and try again.

"Disk N changed or was unplugged since the list was refreshed"

The card was swapped, re-inserted or removed after the list was loaded. Press Refresh, pick the disk again and restart the job.

"The image (…) is bigger than the device"

The target card is smaller than the one the image came from. See Card sizes. Use a bigger card, or shrink the image on Linux with a tool like PiShrink.

"Target … is smaller than source"

Same thing for clone. B has to be at least as big as A.

"Not enough space"

The folder you're saving to doesn't have room for an uncompressed image of the card. Turn on compression, or save somewhere else.

During a job

MessageWhat it means
Access deniedSomething still has the disk open, or the card is write-protected. Close other programs and check the lock switch.
The device is write-protectedSlide the little lock switch on the SD card or adapter up (away from the contacts).
The device isn't readyThe card or reader went away. Was it unplugged or did the cable wobble?
Data error (CRC)The card has bad sectors. It's dying. Get the data off if you still can and replace it.
Not enough free spaceThe disk you're saving to filled up, usually because the image compressed less than expected.
The device reported a hardware errorThe card or reader failed. Try a different reader before blaming the card.
I/O errorThe card or reader is failing, or it was unplugged.
The device was disconnectedJust that. Check the USB connection. Front-panel ports and hubs are a frequent cause.
Short read / Short write at byte …The device stopped answering mid-job. Usually unplugged or a flaky USB connection.

Each of these ends with the Windows function and error code in brackets. Handy if you report a bug.

Verify failures

"Read-back check failed: the device didn't keep what was written"

What was read back from the card isn't what was written. The card is worn out or fake. Run the job again with a different card. If it happens on several cards, try another reader or USB port.

To test a card's real capacity, use a tool like H2testw (Windows) or F3 (Linux/macOS).

"The image file doesn't match what was read from the device"

This one's on the PC side: the backup file didn't come out the same as what was read from the card. The disk you saved to may be failing. Try saving somewhere else.

"The image doesn't match its .hash.txt file, so it's damaged"

The image file has changed since the backup was made: a bad download, a failing drive, or a copy that got cut short. The card was left blank. Use another copy of the backup if you have one. If you're sure the image is fine and the hash file is the wrong one (say you renamed files and mixed them up), move the .hash.txt away and the restore will go ahead without that check.

After a job

"The device is now blank or only partly written"

A restore or clone was cancelled or failed. That's the safety net working. Run it again before putting the card in a Pi.

Windows asks to format the card

Windows can't read Linux partitions, so it offers to format them. Click Cancel.

The card is bigger than the image and the extra space is missing

Expected. The partitions are exactly as they were on the original card. Expand the filesystem on the Pi with sudo raspi-config → Advanced Options → Expand Filesystem.

The backup is much bigger than the space in use

Deleted files leave old data behind, which doesn't compress. See the free-space tip on Image formats.

Speed

The speed shown is averaged over the last few seconds. Some rough numbers for what's normal:

  • USB 2.0 readers top out around 20 to 40 MB/s.
  • A good USB 3 reader with a decent card reads at 80 to 100 MB/s or more.
  • Writes are usually slower than reads, sometimes a lot slower on cheap cards.

If it's slower than you'd expect, try a USB 3 port on the back of the PC rather than a hub or front-panel port. The app reads and writes at the same time with a 32 MiB buffer in between, so the slower of the two devices sets the pace.

Still stuck?

Open an issue on GitHub with the exact error text, what you were doing, your Windows version and the card/reader model.
