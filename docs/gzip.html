Image formats

Plain and gzip images, and why the compression is set the way it is.

.img

A plain, byte-for-byte copy of the card. It's exactly as big as the card. Other tools such as Raspberry Pi Imager, balenaEtcher, Win32 Disk Imager or dd can all write it, and on Linux you can mount its partitions with a loop device.

.img.gz

The same thing, gzip-compressed. Most of a Pi card is empty or zeroed space, so these are usually far smaller than the card. Raspberry Pi Imager and balenaEtcher can write .img.gz files directly too, and on any system you can turn one back into a plain image with:

gunzip -k pihole.img.gz

(On Windows, 7-Zip does the same.)

Compression level

Backups use gzip level 1, the fastest. On SD card images it gives nearly the same size as level 9, because the space savings mostly come from empty areas, which every level squashes equally well. Higher levels just make the CPU the slowest part of the job.

One thing to know: space that once held files and was deleted still contains the old data, and doesn't compress well. If a backup is bigger than you expect, you can zero the free space on the Pi before backing up:

sudo sh -c 'dd if=/dev/zero of=/zero.fill bs=4M status=progress; rm /zero.fill; sync'

dd stops with "No space left on device". That's expected, and the file is deleted straight after. The disk is completely full for a few seconds, so stop anything busy (databases, logging-heavy services) first.

How a gzip image is recognised

By its first two bytes, not its name. Rename it to anything you like and restore still handles it.
