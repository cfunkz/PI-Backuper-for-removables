Safety checks

Raw disk tools can wipe the wrong drive in one click. Here's everything PI-Backuper does to make that hard.

Only removable disks are listed

The lists only show disks Windows reports as USB or removable media. Internal SATA and NVMe drives never appear. On top of that, the disk Windows itself runs from is always skipped, even if it happens to be on USB. Card readers with no card in them are hidden too.

The right disk, every time

Windows reuses disk numbers. If you pull a card and plug in another one, "Disk 2" can now be a different card. So each disk is remembered by its number, hardware ID, serial and exact size. When you start a job, and again right after you click Yes in the erase dialog, the disk is looked up fresh and all of those have to match. If not, you get "Disk N changed or was unplugged since the list was refreshed. Press Refresh and pick it again."

Confirmation before erasing

Restore and clone always ask first, with a warning dialog that names the disk in full. The default button is No, so a stray Enter key does nothing.

Never your own files

  • You can't save a backup onto the card you're backing up.
  • You can't restore an image that's stored on the card you're restoring to.

No half-restored cards

Restore and clone blank the first 4 MiB of the target before writing anything else, and write the real data there last. That area holds the partition table. Until the very end, the card has no partitions as far as any computer is concerned.

Why it matters: a card that's 90% restored still has a valid partition table and will happily boot, then fall over in strange ways later because half its files are from the old system. A blank card is obviously broken and you just run the restore again.

This covers cancel, errors, a pulled cable and a power cut.

Damaged images are caught

If the image has a .hash.txt, its hash is worked out as it's written. A mismatch stops the restore before the partition table goes on, so the card stays blank. See Verification and hashes.

Size checks

  • An image bigger than the target is refused before writing starts, whenever the size is known.
  • When it isn't known up front (a gzip image with no hash file), writing stops the moment it would go past the end of the card.
  • Clone refuses a target smaller than the source.

No half-written backups

Backups are written to name.partial and only get their real name after they're complete, flushed and verified. On cancel or error the partial file is deleted. An existing backup with the same name is never touched until the new one is ready.

Nothing else touches the card

Before writing, every volume on the target is locked and dismounted. That stops Windows, Explorer, antivirus or anything else from writing to the card while it's being overwritten. If a volume can't be locked, the job doesn't start. The lock is retried for a few seconds first, because Explorer and antivirus often hold a disk open briefly.

Source disks (backup, and A in a clone) are locked too when Windows allows it, but not dismounted. If that lock fails you get a note and the job carries on.

Free space

An uncompressed backup won't start if the folder hasn't got room for the whole card. A compressed one warns you and lets you decide.

No sleep mid-job

Windows is told to stay awake while a job runs, so a long backup on a laptop doesn't get cut off by the sleep timer. (Closing the lid can still put it to sleep, depending on your power settings.)

Closing the window

If you close the app while a job is running, it asks first. Saying yes cancels the job cleanly (deleting partial files, leaving cards blank rather than half-written) and then closes.

Plain-English errors

Common Windows errors such as "write-protected", "device not ready" or "data error (CRC)" are turned into a sentence that says what's actually wrong. See Troubleshooting.
